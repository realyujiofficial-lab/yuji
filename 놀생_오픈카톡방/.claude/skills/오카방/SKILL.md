# 오카방 분석 오케스트레이터

**실행 모드:** 서브 에이전트 (파이프라인)

운영자(닭국밥)가 "오카방 분석해줘" 한 마디로 최신 분석 리포트를 받을 수 있도록 데이터 갱신 → 통계 추출 → 분석 리포트 생성을 자동화한다.

## 경로 상수

```
BASE  = /mnt/c/Users/ryu53/Downloads/깃허브/harness-main/놀생_오픈카톡방
SKILL = {BASE}/.claude/skills/오카방
```

---

## Phase 0: 컨텍스트 확인

`_workspace/stats.json` 존재 여부와 생성 시각을 확인한다.

- **파일 없음** → 초기 실행 (Phase 1부터)
- **파일 있음 + 오늘 생성** → 사용자가 "다시" / "재분석" 요청하면 Phase 1부터, 아니면 Phase 3으로 바로
- **파일 있음 + 어제 이전** → Phase 1부터 (데이터 갱신 필요)

---

## Phase 1: 데이터 갱신

### 1-1. 대화기록 정제본 갱신

```bash
cd {BASE}
python3 스크립트/process_chat.py
```

실패하면 경고 출력 후 기존 정제본으로 계속 진행한다.

### 1-2. 통계 추출

```bash
python3 {SKILL}/scripts/extract_stats.py
```

`_workspace/stats.json` 생성을 확인한다.

---

## Phase 2: 분석 옵션 파악

사용자 요청 유형을 분류한다:

| 요청 유형 | 예시 | Phase 3 지시 |
|---|---|---|
| 오늘 분석 | "오늘 반응", "오늘 어때" | 오늘 + 최근 7일 트렌드 |
| 기간 비교 | "이전이랑 비교", "전후 비교" | 특정 이벤트 전후 구간 비교 |
| 멤버 현황 | "활성 멤버", "이탈 위험" | 멤버 활동 집중 분석 |
| 전체 리포트 | "분석해줘", "현황" | 전체 리포트 (기본) |

비교 요청에 이벤트가 명시되면 (예: "옴팡 전후") 해당 날짜 기준을 analyst에게 전달한다.

---

## Phase 3: chat-analyst 서브 에이전트 호출

아래 내용을 포함한 프롬프트로 `chat-analyst` 에이전트를 호출한다:

```
역할: chat-analyst
파일: {BASE}/_workspace/stats.json 읽기
분석 요청: {Phase 2에서 파악한 요청 유형 + 구체적 지시}
운영자: 닭국밥 (전북 군산&서울 송파/로컬여행/닭국밥)

오늘 날짜: {오늘 날짜}
특이사항: {사용자가 언급한 이벤트/멤버/기간}

{BASE}/.claude/agents/chat-analyst.md 의 출력 형식을 따라 리포트를 생성하라.
오늘 샘플 대화가 stats.json에 있으면 주요 흐름을 3줄로 요약하라.
```

---

## Phase 4: 결과 출력

chat-analyst의 리포트를 그대로 사용자에게 전달한다.
리포트 하단에 다음을 덧붙인다:

```
---
📁 stats.json: {BASE}/_workspace/stats.json
🕐 생성: {stats.json의 generated_at}
```

## Phase 5: 대시보드 업데이트 (선택)

사용자가 "대시보드 업데이트", "사이트 반영", "push해줘" 등을 요청하거나,
Phase 1에서 새 데이터가 생성된 경우 자동으로 실행한다.

```bash
python3 {SKILL}/scripts/update_dashboard.py
```

실패 시: git remote 미설정 안내 → 수동 push 가이드 제공

## 에러 핸들링

- `process_chat.py` 실패 → 기존 정제본으로 계속, 경고 표시
